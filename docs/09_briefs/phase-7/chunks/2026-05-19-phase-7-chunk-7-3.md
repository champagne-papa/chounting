## §4 Partial-information value picks

### Value pick #1 — Per-document-type extractor field shapes

Per agent_architecture_policy.md §2.1 enumeration + ADR-0014 §8 AI fallback contract + ADR-0011 §6+§11 substrate.

**vendor_invoice extractor (11 fields):** `amount` (per line + total) + `currency` + `vendor_id` + `vendor_invoice_number` + `accounting_date` + `account_code` (per line) + `tax_code_id` (per line if present) + `due_date` + `line_items` (array of `{description, amount, account_code, tax_code_id}` per ADR-0011 §11 bill-line schema + ADR-0014 §8 field-extraction schemas mandate per-line extraction) + bank-detail fields (Tier 2.5 only at commit; chunk 7.3 extractor does NOT extract bank-detail fields at v1 per ADR-0007 §Tier 2 read boundary).

**receipt extractor (8 fields):** `merchant`/`vendor` (free-text or vendor_id) + `date` (transaction date) + `amount` (subtotal + total) + `currency` + `payment_method` + `last_4`/card-account identifier + `merchant_identifier`/`auth_ref`/`transaction_reference` + `tax_amount` (if present).

**payment_confirmation extractor (7 fields):** `vendor` (vendor_id or free-text) + `payment_date` + `amount` + `currency` + `payment_method` + `payment_reference`/`auth_ref`/`transaction_id` + `cited_invoice_number`/`cited_bill_id` (if present in confirmation).

**line_items shape resolution:** per-line `{description, amount, account_code, tax_code_id}` per ADR-0011 §11 + ADR-0014 §8. Single aggregate total NOT supported at v1 (loses per-line account_code which is required for bill posting per Phase 5 substrate).

**tax_amount resolution:** extracted directly from document text (not computed from subtotal + rate). If not present in document, mark as null and require user input at Tier 1 re-verification per Q28 matrix.

### Value pick #2 — Per-extractor rule-based extraction strategy

Per-extractor implements Tier A rule-based extraction first (regex + heuristic baselines); Tier C AI fallback fires if Tier A extraction produces null/invalid for required fields per Zod schema. Per ADR-0014 §8 + agent_architecture_policy.md §2.1.

**vendor_invoice rule-based baseline:**
- `vendor_invoice_number`: regex matching "Invoice #|Invoice No|Bill #" + digit sequence
- `amount/total`: regex matching currency symbols + digit-period sequences in totals section
- `accounting_date` / `due_date`: regex matching date formats; due_date inference from "Due:" or "Net 30" terms
- `line_items`: table-extraction heuristic (rows + columns; column-header inference for amount + description)

**receipt rule-based baseline:**
- `merchant`: header position + capitalization heuristic
- `date` / `amount` / `payment_method` / `last_4`: regex patterns matching common receipt formats
- `merchant_identifier`/`auth_ref`: regex matching "Auth #|Reference|Transaction"

**payment_confirmation rule-based baseline:**
- `payment_reference`: regex matching "Reference|Transaction ID|Auth"
- `payment_date` / `amount` / `payment_method`: regex patterns
- `cited_invoice_number`: regex matching "Invoice #" + digit sequence (rare; most confirmations cite by reference)

**Tier C AI fallback:** per-extractor system prompt invokes Claude (or analogous LLM provider per ADR-0014 §3 sidecar topology) with `document_artifacts.lines` content + per-document-type field-extraction Zod schema; max 2 calls per source document per ADR-0014 §8 Tier C call budget. NEVER passes raw image bytes (preserves engine-agnostic boundary + Q30 byte-for-byte reproducibility).

### Value pick #3 — Vendor matcher matching strategy

Per ADR-0014 §9 VendorMatchResult shape `{vendor_id, confidence, match_type, candidate_alternatives}` + match_type enum `'exact_name' | 'alias' | 'tax_id' | 'email' | 'domain' | 'fuzzy_name' | 'no_match'`:

**Strategy: sequential cascade per match_type strength** (matcher attempts each strategy in order until match confidence exceeds threshold or all strategies exhausted):

1. `exact_name` (case-insensitive ILIKE; confidence 1.0)
2. `alias` (case-insensitive ILIKE against vendor aliases JSONB column; confidence 0.95)
3. `tax_id` (exact match against vendor.tax_id; confidence 1.0)
4. `email` (exact match against vendor.email; confidence 0.90)
5. `domain` (extract from email or URL; exact match against vendor email domain; confidence 0.85)
6. `fuzzy_name` (trigram similarity ≥0.80; confidence per similarity score)
7. `no_match` (no candidates above threshold)

**Confidence threshold:** v1-fixed default 0.80 per ADR-0014 §9; vendor_matcher threshold is NOT a reserved org_settings column at v1 (ADR-0019 enumerates per-document-type confidence_threshold_* + ambiguity_margin + governance columns; vendor_matcher threshold lives in ADR-0014 §9 fixed default until post-v1 org_settings activation per ADR-0017 Decision item 4).

**candidate_alternatives:** list of top-3 candidates below confidence threshold (UX-visible for human review at ProposedEntryCard / ProposedAttachmentCard).
