### Amendment §1 — Sub-Q4 amends to 2-step at chunk 6.1, 3-step total across chunks

Activation trigger codified explicitly: **Step C + Step D activate when migration 137's RPC is amended to require `ingest_batch_id` OR when `documentPlatformService.createSourceDocument` is verified to always pass it.** Most likely chunk 6.2 (drag-drop ships first; `ingestionService.handleDragDropUpload` is the first caller that constructs a batch and may amend the existing service path).

### Amendment §2 — sentinel-batch rows are substrate-valid but never the result of a new ingestion event

The sentinel batches inserted by Sub-Q4 Step B fallback carry `channel_metadata @> '{"sentinel": true, "migration": 152}'::jsonb`. Service-layer Zod at chunks 6.2/6.3 (`ingestBatch.schema.ts` for drag-drop + forwarded_mailbox discriminated unions) must handle sentinel batches as a valid substrate state but NEVER the result of a service-layer ingest call. Chunks 6.2/6.3 brief-drafting flag: **the `ingestBatch.schema.ts` discriminated union must explicitly exclude `{sentinel: true}` shape from drag_drop_pdf / forwarded_mailbox / direct_upload / api_ingest discriminator membership**, OR add an explicit `sentinel` discriminator value that the service code never emits.

This is a forward-pointing test requirement codified at chunk 6.1; not in scope at chunk 6.1 (no Zod schema ships at chunk 6.1). Carry-forward to chunks 6.2/6.3 brief-drafting.

### Atomic RPC — `create_ingest_batch_with_documents_with_audit`

Per Sub-Q5 lock. Signature + body shape:

```sql
CREATE OR REPLACE FUNCTION create_ingest_batch_with_documents_with_audit(
  p_batch        JSONB,
  p_documents    JSONB,  -- jsonb array
  p_cases        JSONB,  -- jsonb array
  p_case_sources JSONB,  -- jsonb array (may be empty)
  p_jobs         JSONB,  -- jsonb array
  p_audit        JSONB
) RETURNS UUID AS $$
DECLARE
  v_batch_id UUID;
  v_doc      JSONB;
  v_case     JSONB;
  v_link     JSONB;
  v_job      JSONB;
BEGIN
  -- p_batch.id is caller-pre-generated (storage path needs batch_id
  -- before source_documents INSERT). Echoed back in RETURN.
  v_batch_id := (p_batch->>'id')::uuid;

  -- INSERT 1: ingest_batches (1 row)
  INSERT INTO ingest_batches (
    id, org_id, ingest_channel, received_at, channel_metadata,
    trace_id, created_at, created_by
  )
  VALUES (
    v_batch_id,
    (p_batch->>'org_id')::uuid,
    (p_batch->>'ingest_channel')::ingest_channel,
    (p_batch->>'received_at')::timestamptz,
    (p_batch->'channel_metadata'),
    (p_batch->>'trace_id')::uuid,
    COALESCE((p_batch->>'created_at')::timestamptz, NOW()),
    p_batch->>'created_by'
  );

  -- INSERT 2..N+1: source_documents (jsonb_array_elements iteration)
  FOR v_doc IN SELECT * FROM jsonb_array_elements(p_documents) LOOP
    INSERT INTO source_documents (
      id, org_id, legal_entity_id, storage_provider, original_storage_key,
      original_content_hash, original_byte_size, original_filename,
      mime_type, ingest_channel, ingest_batch_id, storage_status,
      received_at, created_by
    )
    VALUES (
      (v_doc->>'id')::uuid,
      (v_doc->>'org_id')::uuid,
      NULLIF(v_doc->>'legal_entity_id', '')::uuid,
      (v_doc->>'storage_provider')::storage_provider,
      v_doc->>'original_storage_key',
      v_doc->>'original_content_hash',
      (v_doc->>'original_byte_size')::bigint,
      v_doc->>'original_filename',
      v_doc->>'mime_type',
      (v_doc->>'ingest_channel')::ingest_channel,
      v_batch_id,  -- always populated from outer scope
      COALESCE((v_doc->>'storage_status')::storage_status, 'pending_initial_verify'),
      (v_doc->>'received_at')::timestamptz,
      v_doc->>'created_by'
    );
  END LOOP;

  -- INSERT N+2..N+M+1: document_cases
  FOR v_case IN SELECT * FROM jsonb_array_elements(p_cases) LOOP
    INSERT INTO document_cases (
      id, org_id, document_type, state, trace_id, created_by
    )
    VALUES (
      (v_case->>'id')::uuid,
      (v_case->>'org_id')::uuid,
      (v_case->>'document_type')::document_type,
      COALESCE((v_case->>'state')::document_case_state, 'received'),
      (v_case->>'trace_id')::uuid,
      v_case->>'created_by'
    );
  END LOOP;

  -- INSERT N+M+2..: document_case_sources (may be empty array; loop is no-op)
  FOR v_link IN SELECT * FROM jsonb_array_elements(p_case_sources) LOOP
    INSERT INTO document_case_sources (
      id, document_case_id, source_document_id, role, trace_id, created_by
    )
    VALUES (
      (v_link->>'id')::uuid,
      (v_link->>'document_case_id')::uuid,
      (v_link->>'source_document_id')::uuid,
      (v_link->>'role')::document_case_source_role,
      (v_link->>'trace_id')::uuid,
      v_link->>'created_by'
    );
  END LOOP;

  -- INSERT ...: document_jobs
  FOR v_job IN SELECT * FROM jsonb_array_elements(p_jobs) LOOP
    INSERT INTO document_jobs (
      id, org_id, source_document_id, document_case_id, ingest_batch_id,
      state, trace_id, created_by
    )
    VALUES (
      (v_job->>'id')::uuid,
      (v_job->>'org_id')::uuid,
      (v_job->>'source_document_id')::uuid,
      (v_job->>'document_case_id')::uuid,
      v_batch_id,  -- always populated from outer scope
      COALESCE((v_job->>'state')::document_job_state, 'queued'),
      (v_job->>'trace_id')::uuid,
      v_job->>'created_by'
    );
  END LOOP;

  -- INSERT (final): audit_log — single audit row at batch grain
  INSERT INTO audit_log (
    org_id, user_id, trace_id, action, entity_type, entity_id,
    before_state, after_state_id, tool_name, idempotency_key, reason
  )
  VALUES (
    NULLIF(p_audit->>'org_id', '')::uuid,
    NULLIF(p_audit->>'user_id', '')::uuid,
    (p_audit->>'trace_id')::uuid,
    p_audit->>'action',
    p_audit->>'entity_type',
    v_batch_id,
    p_audit->'before_state',
    NULLIF(p_audit->>'after_state_id', '')::uuid,
    p_audit->>'tool_name',
    NULLIF(p_audit->>'idempotency_key', '')::uuid,
    p_audit->>'reason'
  );

  RETURN v_batch_id;
END;
$$ LANGUAGE plpgsql SECURITY INVOKER;

GRANT EXECUTE ON FUNCTION create_ingest_batch_with_documents_with_audit(JSONB, JSONB, JSONB, JSONB, JSONB, JSONB)
  TO service_role;
```

**audit_log.org_id sourcing:** Phase 6 RPC writes single audit
row at batch grain. org_id comes from the audit payload directly
(`p_audit->>'org_id'`), NOT via parent-table subquery — because
the audit references `ingest_batches.id` (the batch we just
INSERTed) and the subquery would either tautologically read what
we just wrote, or require a complex multi-table subquery for the
batch we don't know is in the table yet at the audit-INSERT
point. The direct payload pattern matches migration 137's RPC
(line 132-143). Future RPCs in chunk 6.2 / 6.3 follow this
shape; chunk 6.2 / 6.3 may add a parent-table-derived pattern
for per-row audits at Phase 7 transitions, but Phase 6's
single-batch-grain audit takes the direct payload.

### Immutability + DELETE-restriction asymmetry

Per Option C (workflow-class asymmetry, chunk-1-Phase-2
precedent at migration 143):

| Table | RLS | Column immutability | DELETE | TRUNCATE |
|---|---|---|---|---|
| `ingest_batches` | 4 policies (select / insert / update / no_delete) | trigger blocks UPDATE on `id`, `org_id`, `ingest_channel`, `received_at`, `channel_metadata`, `trace_id`, `created_at`, `created_by` | BEFORE DELETE trigger | NOT blocked (workflow-class) |
| `document_jobs` | 4 policies | trigger blocks UPDATE on `id`, `org_id`, `source_document_id`, `document_case_id`, `ingest_batch_id`, `trace_id`, `created_at`, `created_by` (mutable: state, attempt_count, started_at, completed_at, last_error_*, pipeline_trace_id) | BEFORE DELETE trigger | NOT blocked (workflow-class) |

No `REVOKE TRUNCATE` for either table. Workflow-class rows are
not bulk-managed evidence anchors per chunk-1-Phase-2 chunk-zero
adjudication; the load-bearing concern is audit_log referent
integrity (catch service_role bypass via BEFORE DELETE).
TRUNCATE protection is skipped as cargo-cult for this row class.

## Walkable proof

**Service-walkable-via-RPC** per chunk-1-Phase-2 precedent
(migration 143). Migration applies cleanly; the atomic RPC
executes transactionally from psql against seed data; INSERT-
with-audit commits across all 5 tables atomically; substrate is

   N-cases + 0-case_sources + N-jobs JSON arrays. All rows land

   violation; Layer 1 CHECK violation); all-or-nothing transaction

   row.
