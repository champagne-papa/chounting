### Amendment §1 — γ' re-eval primitive (rematchCandidate spec)

Replaces brief Task 4 step 3 ("Per trigger_type: load case + execute Subsystem 1 (`completeCandidate`) with appropriate input shape (reconstruct CompleteCandidateInput from case + source_document); collect new candidate set").

**rematchCandidate(case_id, trace_id, ctx) → Promise<DocumentRelationshipCandidate[]>** private helper. Logic:

1. Load case's candidates via `loadCandidatesForCase`. Pick first head-of-chain (supersedes_candidate_id IS NULL) as priorCandidate.
2. **If no prior candidate: return empty array.** This is the γ'-partial path — stranded cases (T1/T3/T4 fan-out scope; T10-without-priors) hit this branch by definition. Empty array is semantically correct, not a bug; caller (runPerCaseReEvaluation) maps to decision_outcome='no_change' per the 6-rule discriminator (§3 below).
3. Reconstruct partial CompleteCandidateInput from `priorCandidate.candidate_features` (six fields direct per chunk-1 ship verification): document_type, classification_confidence, vendor_match_type, vendor_match_confidence, extracted_amount, extracted_invoice_date.
4. Derive vendor_match.vendor_id via linked_entity_id fallback:
   - linked_entity_type='bill' → SELECT vendor_id FROM bills WHERE id=priorCandidate.linked_entity_id
   - linked_entity_type='vendor_prepayment' → SELECT vendor_id FROM vendor_prepayments WHERE id=priorCandidate.linked_entity_id
   - Other linked_entity_types: defensive log + return [] (paymentService/vendorCreditService deferred per Round 1 finding; these shouldn't appear at v1 fan-out)
5. Call `completeCandidate(reconstructedInput, ctx)` and return result.

rematchCandidate is on disk (~110 lines including comments) at the current uncommitted working-tree state.

### Amendment §4 — D-partial-no-idempotency

Replaces the implicit assumption in the original brief that completeCandidate would skip re-emitting candidates when "new output matches current candidate" (ADR-0018:792-805 idempotency contract).

**Reality**: chunk-1's completeCandidate dedups against `source_document_links` only (via `existingPairKey` filter at line 615+); does NOT dedup against existing `document_relationship_candidates` rows. Every non-empty re-run inserts new candidate rows in addition to existing ones. count_after > count_before strictly for any T5/T8/T10-with-priors re-run that produces a non-empty result.

**Operational consequences at v1**:
- T8 period reopen on case whose candidate set didn't actually change → emits `candidate_superseded` even though output is identical to prior (noisy audit event)
- T5/T6/T8 partial-state-change where some candidates still match → emits `candidate_superseded` even for the matching subset (spurious supersession chains)
- T10 manual reprocess where state hasn't changed since prior run → emits `candidate_superseded` even though re-eval is a no-op (noise)

**Acceptable at v1** with low trigger volume; defers ADR-0018-conformant idempotency activation to a future chunk that implements fingerprint-based dedup. RI-9 tracks the deferral.

**Future-chunk activation**: when operational evidence shows the noise + supersession-chain growth becomes problematic (or proactively at Phase 7 ship + Phase 4 retrospective consolidation), a future chunk implements classifier_output_fingerprint + domain_state_fingerprint dedup per ADR-0018:802-805. Existing supersession chains stay; new re-runs use fingerprint dedup.

```typescript
function deriveDispatchIdempotencyKey(
  case_id: string,
  trigger_type: string,
  trace_id: string,
): string {
  const hex = createHash('md5')
    .update(`${case_id}:${trace_id}:${trigger_type}`)
    .digest('hex');
  return `${hex.slice(0, 8)}-${hex.slice(8, 12)}-${hex.slice(12, 16)}-${hex.slice(16, 20)}-${hex.slice(20, 32)}`;
}
```

### `cancel_exception_with_audit` RPC — chunk-6 pattern mirror

Atomic RPC mirroring chunk-6's `enqueue_exception_with_audit` + `resolve_exception_with_audit` shape:

```sql
CREATE OR REPLACE FUNCTION cancel_exception_with_audit(
  p_entry_id UUID,
  p_audit    JSONB   -- mutation audit row payload
) RETURNS UUID AS $$
DECLARE
  v_before_status      exception_status;
  v_document_case_id   UUID;
  v_org_id             UUID;
BEGIN
  -- Capture prior state + parent-derived org_id.
  -- FOR UPDATE locks the row to serialize concurrent dispatcher calls.
  SELECT exception_status, document_case_id, org_id
    INTO v_before_status, v_document_case_id, v_org_id
  FROM exception_queue_entries
  WHERE id = p_entry_id
  FOR UPDATE;

  IF v_before_status IS NULL THEN
    RAISE EXCEPTION 'exception_queue_entry % not found', p_entry_id
      USING ERRCODE = 'no_data_found';
  END IF;

  -- State-transition guard: atomic UPDATE with WHERE exception_status='open'.
  -- If status has drifted to 'resolved' or 'cancelled' (concurrent dispatch
  -- or manual resolve), the UPDATE matches zero rows. RAISE check_violation
  -- maps to EXCEPTION_ALREADY_CANCELLED at the service boundary.
  -- Mirrors chunk-6's enqueue + resolve RPC guard patterns.
  UPDATE exception_queue_entries
  SET exception_status = 'cancelled'
  WHERE id = p_entry_id AND exception_status = 'open';

  IF NOT FOUND THEN
    RAISE EXCEPTION 'exception_queue_entry % not in open status', p_entry_id
      USING ERRCODE = 'check_violation';
  END IF;

  -- Emit mutation audit row (caller-constructed before_state).
  INSERT INTO audit_log (
    org_id, user_id, trace_id, action, entity_type, entity_id,
    before_state, after_state_id, tool_name, idempotency_key, reason
  )
  VALUES (
    v_org_id,
    NULLIF(p_audit->>'user_id', '')::uuid,
    (p_audit->>'trace_id')::uuid,
    p_audit->>'action',                   -- 'exception_cancelled'
    p_audit->>'entity_type',              -- 'exception_queue_entry'
    p_entry_id,
    jsonb_build_object(
      'exception_status', v_before_status::text,
      'document_case_id', v_document_case_id
    ),
    p_entry_id,
    p_audit->>'tool_name',
    NULLIF(p_audit->>'idempotency_key', '')::uuid,
    p_audit->>'reason'
  );

  RETURN p_entry_id;
END;
$$ LANGUAGE plpgsql SECURITY INVOKER;

GRANT EXECUTE ON FUNCTION cancel_exception_with_audit(UUID, JSONB) TO service_role;
```

Mirrors chunk-6's `resolve_exception_with_audit` shape (`SELECT FOR UPDATE` for parent-derived org_id capture + state-transition-guarded UPDATE + RAISE check_violation on guard failure + single audit row emission). The `_with_audit` suffix is retained per F-J-ε convention (the RPC mutates substrate; not pure-audit; F-J-9 demoted to memory-only documents this convention extension with one more instance).

### `reject_invalid_exception_status_transition` trigger rewrite — cancelled-is-terminal symmetry

Chunk-6's trigger function (at `20240148000000_exception_queue_substrate.sql:301-315`) rejected only `resolved → other` transitions. Chunk-3 extends the function with a second IF clause forbidding `cancelled → other` (mirror-framing error message naming the chunk-6 symmetry):

```sql
CREATE OR REPLACE FUNCTION reject_invalid_exception_status_transition()
RETURNS TRIGGER AS $$
BEGIN
  -- Chunk-6: resolved is terminal one-way.
  IF OLD.exception_status = 'resolved'
     AND NEW.exception_status IS DISTINCT FROM 'resolved' THEN
    RAISE EXCEPTION 'exception_queue_entries.exception_status transition resolved → % is forbidden (one-way per ADR-0011 §13 chunk-6 semantics); resolution is permanent', NEW.exception_status
      USING ERRCODE = 'check_violation';
  END IF;

  -- Chunk-3: cancelled is terminal one-way (mirror of chunk-6's resolved).
  IF OLD.exception_status = 'cancelled'
     AND NEW.exception_status IS DISTINCT FROM 'cancelled' THEN
    RAISE EXCEPTION 'cancelled is terminal per ADR-0018 Subsystem 3 contract; cancelled → % is forbidden (mirrors chunk-6 resolved → % one-way rule)', NEW.exception_status, NEW.exception_status
      USING ERRCODE = 'check_violation';
  END IF;

  RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

Per-source-state error messaging preserved (two distinct messages for `resolved → X` vs `cancelled → X`); the chunk-2 codified discipline of stable test regex `_chunk_\d+_active` handles constraint-name shifts at the test-assertion layer separately. The trigger function itself doesn't carry a `_chunk_N_active` suffix (it's a function name, not a constraint name); the function-name `reject_invalid_exception_status_transition` is stable across CHECK broadenings.

> **Phase 4 chunk 3 — T5 emission per-method conditional gating: state-transition watch-set semantics (2026-05-14).** ADR-0018 §T5 specifies T5 fires when bill "leaves ('approved_for_payment', 'partially_paid') states."
