### ADR-0010 three-layer reserved-enum discipline (chunk-5 application)

All three layers ship at chunk 5:
- **Layer 1 (DB CHECK)**: three CHECKs — `linked_entity_type_chunk_5_active` (8-value IN list), `link_role_chunk_5_active` (4-value IN list), `source_document_links_pair_validity_chunk_5_active` (row-constructor IN over 15 verbatim pairs from ADR-0016 §3 Table A).
- **Layer 2 (Zod)**: enum literal unions for `LinkedEntityTypeSchema` (8 values) + `LinkRoleSchema` (4 values) + `LinkStatusSchema` (2 values), plus `CreateSourceDocumentLinkInputSchema.refine()` enforcing the 15-pair matrix.
- **Layer 3 (service)**: `documentLinkService.create()` body emits only INSERTs with v1-active values + valid pairs. Two distinct error categories — DO NOT conflate:
  - **`LINKED_ENTITY_NOT_FOUND` — runtime integrity check (reachable in production).** The 8-case polymorphic validator returns this `ServiceError` when a Zod-valid input references an entity that doesn't exist in the target table. A caller passes a well-formed UUID for a nonexistent entity (a deleted bill, a typo, a stale id from the proposal queue). MUST be test-exercised; reachable from any production caller. Tested in Describe 3.
  - **`PAIR_RESERVED_POST_V1`, `PAIR_INVALID` — defense-in-depth backstops** per ADR-0016 §4. Not expected to fire in normal v1 operation (Zod parse at Layer 2 catches them first). NOT test-exercised at chunk 5 because the path to reach them requires bypassing the type system (the production input shape forbids the value).

Constraint naming: `_chunk_5_active` (chunks 1-2 incremental-broadening precedent — `linked_entity_type` and `link_role` will broaden chunk-by-chunk in later phases as new entity types and roles activate). Stable test regex: `/source_document_links_(linked_entity_type|link_role|pair_validity)_chunk_\d+_active/`.

### §6(a) + §6(b) two-mechanism state mutation control

Two complementary mechanisms compose to enforce post-commit immutability + one-way state transition:

**§6(a) — column-level GRANT/REVOKE for service_role** (codebase-novel pattern; chunks 1-4 didn't use):
```sql
REVOKE UPDATE ON source_document_links FROM service_role;
GRANT UPDATE (link_status) ON source_document_links TO service_role;
REVOKE DELETE ON source_document_links FROM service_role;
```
Service_role can UPDATE only the `link_status` column. Direct DELETE blocked at GRANT level; `ON DELETE CASCADE` from `source_documents` still works (cascade fires at table-owner level, bypassing GRANT/REVOKE — verified empirically at Task 4 test).

**§6(b) — column-list BEFORE UPDATE OF link_status trigger** for the one-way transition CHECK:
- Fires only when `link_status` is being mutated (column-list trigger narrows surface).
- Function rejects `OLD.link_status = 'reversed' AND NEW.link_status = 'created'` regression with `feature_not_supported` ERRCODE.
- Mirrors chunks 1-4's `reject_<table>_mutation()` function naming pattern.

Composition: GRANT enforces "which columns are mutable" (only `link_status`); trigger enforces "valid transitions on the mutable column" (no `reversed → created` regression). No overlap; clean architecture. Migration top-comment names the composition explicitly.

### Polymorphic integrity validator — 8-case switch inside `create()`

ADR-0011 §4 constraint 3: SQL polymorphic FKs are not enforceable (the `linked_entity_id` column references one of N tables depending on `linked_entity_type`). The integrity check lives in `documentLinkService.create()` after the Zod parse: an 8-case switch on `linked_entity_type` calls a 1-line existence check (`SELECT 1 FROM <table> WHERE id = $1`) and throws `ServiceError('LINKED_ENTITY_NOT_FOUND', ...)` on miss.

The 8 cases match the v1-active `linked_entity_type` subset: `bill` → `bills`, `bill_line` → `bill_lines`, `payment` → `payments`, `bill_payment_allocation` → `bill_payment_allocations`, `vendor_prepayment` → `vendor_prepayments`, `vendor_prepayment_application` → `vendor_prepayment_applications`, `vendor_credit` → `vendor_credits`, `vendor_credit_application` → `vendor_credit_applications`. Future broadening (chunk 6 adds vendor; later phases add customer-side entities) extends the switch.

Self-contained; no new abstractions; no registry pattern.

### Cascade behavior — bulk by (entity_type, entity_id)

ADR-0016 §5 specifies `reverseLinkedEntityLink` as a **bulk operation** by `(linked_entity_type, linked_entity_id)`, NOT single-row by link_id:

> The function looks up all `source_document_links` rows where `(linked_entity_type, linked_entity_id)` matches the input AND `link_status = 'created'`; for each matching row, it updates `link_status` to `reversed` and emits a `source_document_link_reversed` audit event through the canonical audit-log writer.

Input per §5: `(linked_entity_type, linked_entity_id, reversal_trace_id, controller_user_id)`. Chunk 5 adds `reversal_reason` as a 5th input field because the `source_document_link_reversed` audit event spec (ADR-0016 §Reserved-enums-and-audit-events) requires it but §5's 4-field signature omits it — surfaced as a flagged ambiguity below.

Domain caller pattern (post-v1 wiring; out of scope for chunk 5): `paymentService.commitFailureReversal(...)` → `documentLinkService.reverseLinkedEntityLink('payment', payment_id, reversal_reason, trace_id, controller_user_id)` inside the same `withInvariants()` transaction as the payment-state flip and reversal journal entry.

### Single-writer rule on link_role role for case-source-vs-domain-link distinction

`document_case_sources.role` (chunk 3) and `source_document_links.link_role` (chunk 5) are **distinct columns on distinct tables** with **overlapping but separate vocabularies**:
- `document_case_sources.role`: scoped to case-level workflow (`primary`, `supporting`, `email_body`, `payment_evidence`, plus 2 reserved).
- `source_document_links.link_role`: scoped to domain-entity attachment (`primary_invoice`, `payment_evidence`, `receipt`, `supporting`, plus 23 reserved).

The two columns share two value strings (`payment_evidence`, `supporting`) but are different ENUMs and serve different semantics (case workflow vs domain entity). Don't conflate.

GRANT UPDATE (link_status) ON source_document_links TO service_role;

-- -----------------------------------------------------------
-- §6(b) column-list trigger: BEFORE UPDATE OF link_status only.
-- Rejects reversed → created regression. Narrow firing surface;
-- only fires when link_status is being mutated.
-- -----------------------------------------------------------
CREATE OR REPLACE FUNCTION reject_source_document_links_status_regression()
RETURNS TRIGGER AS $$
BEGIN
  IF OLD.link_status = 'reversed' AND NEW.link_status = 'created' THEN
    RAISE EXCEPTION 'source_document_links.link_status transition reversed → created is forbidden (one-way per ADR-0016 §6(b)); reversal is permanent'
      USING ERRCODE = 'feature_not_supported';
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_source_document_links_status_one_way
  BEFORE UPDATE OF link_status ON source_document_links
  FOR EACH ROW
  EXECUTE FUNCTION reject_source_document_links_status_regression();

-- -----------------------------------------------------------
-- create_source_document_link_with_audit RPC.
-- Mirrors chunk-3 attach_document_case_source_with_audit shape
-- with parent-derived org_id (subquery from source_documents).
-- Single-purpose per chunk-zero adjudication.
-- -----------------------------------------------------------
CREATE OR REPLACE FUNCTION create_source_document_link_with_audit(
  p_link  JSONB,
  p_audit JSONB
) RETURNS UUID AS $$
DECLARE
  v_link_id UUID;
BEGIN
  -- INSERT 1: source_document_links
  INSERT INTO source_document_links (
    id, source_document_id, linked_entity_type, linked_entity_id,
    link_role, link_status, trace_id, created_by
  )
  VALUES (
    (p_link->>'id')::uuid,
    (p_link->>'source_document_id')::uuid,
    (p_link->>'linked_entity_type')::linked_entity_type,
    (p_link->>'linked_entity_id')::uuid,
    (p_link->>'link_role')::link_role,
    'created',
    (p_link->>'trace_id')::uuid,
    p_link->>'created_by'
  )
  RETURNING id INTO v_link_id;

  -- INSERT 2: audit_log — paired write in same transaction.
  -- audit_log.org_id derived via subquery from source_documents at
  -- INSERT time (NOT from p_audit). Chunk-3 canonical pattern.
  INSERT INTO audit_log (
    org_id, user_id, trace_id, action, entity_type, entity_id,
    before_state, after_state_id, tool_name, idempotency_key, reason
  )
  VALUES (
    (SELECT org_id FROM source_documents WHERE id = (p_link->>'source_document_id')::uuid),
    NULLIF(p_audit->>'user_id', '')::uuid,
    (p_audit->>'trace_id')::uuid,
    p_audit->>'action',
    p_audit->>'entity_type',
    v_link_id,
    p_audit->'before_state',
    NULLIF(p_audit->>'after_state_id', '')::uuid,
    p_audit->>'tool_name',
    NULLIF(p_audit->>'idempotency_key', '')::uuid,
    p_audit->>'reason'
  );

  RETURN v_link_id;
END;
$$ LANGUAGE plpgsql SECURITY INVOKER;

GRANT EXECUTE ON FUNCTION create_source_document_link_with_audit(JSONB, JSONB)
  TO service_role;

-- -----------------------------------------------------------
-- reverse_source_document_link_with_audit RPC.
-- Bulk operation per ADR-0016 §5 — flips ALL link_status='created'
-- rows matching (linked_entity_type, linked_entity_id). Emits
-- one audit_log row per flipped row.
--
-- Returns UUID[] of flipped link rows (may be empty if no
-- matching rows; service treats empty as a valid no-op).
-- -----------------------------------------------------------
CREATE OR REPLACE FUNCTION reverse_source_document_link_with_audit(
  p_input JSONB,
  p_audit JSONB
) RETURNS UUID[] AS $$
DECLARE
  v_flipped UUID[];
  v_link_id UUID;
  v_source_doc_id UUID;
  v_link_role link_role;
  v_org_id UUID;
BEGIN
  -- Bulk UPDATE with RETURNING; capture flipped link_ids for
  -- subsequent per-row audit_log INSERTs.
  WITH flipped AS (
    UPDATE source_document_links
    SET link_status = 'reversed'
    WHERE linked_entity_type = (p_input->>'linked_entity_type')::linked_entity_type
      AND linked_entity_id   = (p_input->>'linked_entity_id')::uuid
      AND link_status        = 'created'
    RETURNING id, source_document_id, link_role
  )
  SELECT array_agg(id) INTO v_flipped FROM flipped;

  -- v_flipped may be NULL (zero matches); coalesce to empty array.
  IF v_flipped IS NULL THEN
    RETURN ARRAY[]::UUID[];
  END IF;

  -- Per-row audit_log INSERT. One event per flipped row.
  -- org_id derived from source_documents via the link row's
  -- source_document_id (parent-derived pattern).
  FOR v_link_id IN SELECT unnest(v_flipped) LOOP
    SELECT source_document_id, link_role
      INTO v_source_doc_id, v_link_role
      FROM source_document_links
      WHERE id = v_link_id;

    SELECT org_id INTO v_org_id
      FROM source_documents
      WHERE id = v_source_doc_id;

    INSERT INTO audit_log (
      org_id, user_id, trace_id, action, entity_type, entity_id,
      before_state, after_state_id, tool_name, idempotency_key, reason
    )
    VALUES (
      v_org_id,
      NULLIF(p_audit->>'controller_user_id', '')::uuid,
      (p_audit->>'reversal_trace_id')::uuid,
      'source_document_link_reversed',
      'source_document_link',
      v_link_id,
      jsonb_build_object('link_status', 'created'),
      NULL,
      NULL,
      NULL,
      p_audit->>'reversal_reason'
    );
  END LOOP;

  RETURN v_flipped;
END;
$$ LANGUAGE plpgsql SECURITY INVOKER;

GRANT EXECUTE ON FUNCTION reverse_source_document_link_with_audit(JSONB, JSONB)
  TO service_role;

async function verifyLinkedEntityExists(

  linkedEntityId: string,

  const db = adminClient();
  const tableMap: Record<LinkedEntityType, string> = {
    bill: 'bills',

    payment: 'payments',
    bill_payment_allocation: 'bill_payment_allocations',

    vendor_prepayment_application: 'vendor_prepayment_applications',
    vendor_credit: 'vendor_credits',
